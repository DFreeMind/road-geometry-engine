# 来源数据管理与整体生成

## 操作流程

1. 在“路线数据”入口选择文件或连接，筛选并加载需要的记录到地图。
2. 在“参与生成的数据”查看已导入来源。展开属性表，可选择显示列、查看字段注释、筛选当前已导入记录、勾选参与或排除、批量移除记录。
3. 每个来源的“更多 → 字段映射”设置一套规则。生成时逐条读取该记录自己的字段值，不把当前编辑路线的属性复制给整个表。
4. 点击“生成全部参与路线”。地图右下的“生成道路”仍只生成当前编辑路线，标题说明其作用范围。
5. 从上方数据入口继续导入，同一文件图层或连接图层追加到既有来源；完全相同记录自动去重。修改过的同 FID 记录保留为不同内容版本，不静默覆盖。

整体生成的“全部”指工程中已经加载且参与生成的记录。路线选择器对支持分页的来源默认继续读取直到末页，没有 500 条或 2,000 条的总量上限；内部传输批次与表格展示页分开。来源级查询读取全部匹配项，表格搜索/表达式筛选覆盖已经读到选择器的全部记录。读取中可停止，保留选择表内已读取记录，再从下一位置继续；关闭选择窗口不自动导入地图。只有确认“加载到地图”才提交所选记录，大选择按 2,000 条分块提交到工程，并只记录一次撤销快照。只支持有界快照的适配器明确提示来源能力和未完整状态，不冒充完整数据。

管理面板的筛选只查找当前已导入数据。移除操作仅影响工程，绝不删除原文件或数据库记录。操作支持工程撤销。

## 几何与属性

- LineString 生成一个连续部件；MultiLineString 的所有部件分别生成，不只选最长部件，也不强行连接不连续线段。不同记录的道路不会自动拼接或消除交叠。
- 每部件使用适合其位置的 UTM 米制坐标调用既有 Rust 几何引擎；显示副本转换为 WGS84。输出按来源、组件和 CRS 聚合，不能把多个投影坐标混作同一 CRS。
- 来源保存独立默认横断面。未映射属性使用该模板；已映射字段的空值默认阻止生成，只有明确启用手动回退才使用模板。
- 历史工程未保存独立模板且当前断面来自映射时，采用程序初始模板作为迁移默认，不拿当前某条记录的映射值填充其他记录；使用旧工程时应复核来源默认横断面。
- 单条路线的人工顶点或横断面编辑保存为覆盖，不改变原始属性与原始几何；整体生成使用覆盖。人工横断面覆盖优先于来源映射。
- 成果保留源属性，以及 `source_attributes`、`source_dataset_id`、`source_feature_key`、`part_index`，用于追溯每个结果。
- 单部件不再限制 2,000 个控制点，保留完整原始折线。场景桩位/要素也移除了 10,000 条总数限制；非法间距、计数溢出或浮点里程无法继续前进时明确报错，不静默截断。本轮没有实现业务桩号区间横断面。

## 成果生命周期

- 取消参与、移除记录或来源，对应成果同步从地图及导出中剔除，剩余记录成果保留。追加记录不丢弃已有成果，新记录需生成。
- 修改来源映射使该来源旧成果失效；修改某条人工覆盖仅使该条旧成果失效，其他来源和记录不受影响。
- 来源数据、映射、参与状态、人工覆盖、成果及校验问题随工程保存。生成期间输入改变或任务取消，整批迟到成果不写入工程。
- 校验问题阻止整批开始，不静默跳过。引擎运行中的个别失败记录报告错误，其余成功记录可以提交；错误列表显示前 100 项，完整结果随工程保存。
- 已成功且单部件几何、横断面、来源属性与几何场景规则相同的成果直接复用，仅计算新增/修改部件。失败部件重试。结果记录计算/复用数量、成功分块数量、引擎进程数和耗时；未实现跨进程断点续跑或人工成果面编辑。
- 路面材质和成果表达是显示选项，切换后保留几何、即时更新显示；成果中的材质属性仍是生成时快照，不冒充重新计算后的数据。

## 性能和边界

逐行映射、任务准备与投影转换放在 Web Worker。整体任务按最多 256 部件/约 8 MiB 请求连续分块，本地按硬件并行度使用 1～4 个工作线程，各线程在一块内复用一个 `--stream` 引擎进程，不再每个碎段启动一次进程。长路线自交检测使用包围盒候选过滤，场景按累计里程二分定位。进度跨块累计，可取消校验和本地生成；没有新增第二套业务几何引擎。

**没有整次导入/生成的 10,000 条数量上限，也没有工程 128 MiB、GeoJSON 256 MiB/百万要素的固定文件上限。** 项目读取/保存和 GeoJSON 导出改为缓冲流式编解码，避免额外持有完整编码字节副本；任务成果不重复保存路线坐标，坐标保留在来源及人工覆盖中。

保留单次 IPC 资源保护：原生每块最多 512 个部件、输入 64 MiB、完整响应 128 MiB；流式引擎每条请求 16 MiB、每条响应 128 MiB。多部件块输出过大时前端自动缩小块重试。单条极端复杂路线仍可能触发资源错误，会明确显示失败，绝不以残缺路线冒充完成。页面每批最多 10,000 条只是传输大小，不是来源总量限制。

目前工程与地图仍持有完整矢量数据，**不是无限内存或百万级按视口存储已验收的承诺**。更大规模下一阶段应迁移工程原始数据/成果到 GeoPackage，采用空间索引、视口查询、显示副本分级简化和有界缓存；数据库分页应进一步采用稳定主键游标，避免深 OFFSET。完整生产几何不能被显示简化替代，不强行拼接断链或不同桥隧层级的碎段。

## 验证

纯模型测试覆盖追加去重、冲突 FID、参与和删除、逐记录不同属性映射、全部多部件、手动覆盖、缺失字段/空值、长路线完整保留、超过万条的连续分页与分块调度、增量复用、按组件/CRS 聚合及结果追溯。原生测试覆盖流式进程复用、逐任务错误隔离、超长行恢复、杀进程取消、10,001 点工程保存重开。真实桌面合成数据验证统一映射、多部件批量生成、地图加载、重复追加、参与排除、部分移除和工程保存重开；不访问业务数据库。

本轮基础验证：前端 91 项通过，桌面 Rust 51 项通过、1 项凭据管理器测试按条件忽略，核心引擎 20 项通过；TypeScript、Prettier、Rust 格式和 Clippy 检查通过。核心 release 单次测量：10,000 点东西向直线引擎计时 52.855 ms，南北向 56.118 ms；一个流式进程处理 1,000 条短碎段，1,000 条响应齐全，墙钟 78.6 ms。这不是完整桌面导入/渲染耗时，也不是受控硬件的性能承诺。

最终真实 WebView2 回归 96 项通过、界面错误 0，报告 `artifacts/maplibre-qa/20261003-234110-143/report.json`；构建 `build-20261003-234015-630`。本机 Intel Core Ultra 9 185H（16 核/22 逻辑线程）、约 32 GiB 内存，桌面 debug + 引擎 release；合成 GeoJSON 10,001 条两点短线、文件 1,532,639 字节、每条两个简单属性、单侧 3m 车道、其他宽度为 0、场景关闭。全量导入约 4.897 秒；生成计时约 5.147 秒（从任务准备完成后到成果提交，不含全部预校验/最终地图渲染），40 块、160 次进程启动，10,001 个部件全部成功并显示在地图。另一遍 500 条批次导入为 13.584 秒，较大读取批次减少了进程往返；不是严格冷缓存 A/B 基准，不能推及复杂几何或 69 字段业务表。峰值内存、百万级数据、独立安装器仍未验收。
