# 匝道几何与生成问题窗口

## 局部偏移修整基础

独立路线偏移不是完整路口建模。急弯内侧可能形成小自交环；多条路线各自生成的边界也可能在汇入位置重叠。二者需要分别处理，不能通过关闭有效性校验或全局合并所有道路来掩盖问题。

第一轮在既有 Rust 引擎中增加有限的局部偏移环修整，基础规则版本为 `offset-local-loops-v2`：

- 原始参考线真正自交时先报告源线段及估算几何里程，不修改原始数据。
- 仅修整偏移边界的一处非共线交叉，交叉线段索引差不超过 8，对应源线跨度不超过偏移绝对值的 4 倍。
- 使用精确交点保留未受影响的首尾边界；多个剩余自交、退化面或组件重叠仍然失败。
- 相邻横断面组件使用相同偏移边界规则；标线、护栏和自动布设点设施也遵循同一规则。点设施在修整区间可能归到交点，数量保留，但位置必须人工复核。
- 每次修整记录 `offset_local_loop_trimmed` 警告，包括偏移、源控制点、估算几何里程和规则版本。估算几何里程不是数据库业务桩号。
- 输入签名包含规则版本，升级后不继续复用旧规则的几何成果。原始输入及人工覆盖不变。

“生成问题”侧栏只保留数量摘要，明细支持搜索和每页 20 条浏览，没有问题总数截断。桌面端现在使用独立原生窗口，可拖到应用外或另一个屏幕；定位不再自动最小化。浏览器预览仍是页面内浮窗，不具备移出浏览器的能力。

校验/生成失败与“需复核”分开。失败项支持修改、字段映射和定向重试，重试全部不重复计算未变更的成功部件；修整后已成功的警告不会冒充失败、自动重试或被静默隐藏。问题及警告随成果保存，来源修订不匹配时不显示陈旧警告。

## 独立问题窗口与大数据编辑改进

独立窗口只加载问题列表，不加载完整 App、MapLibre 或工程原始数据。主窗口同步问题摘要，操作只回传问题 ID，由主窗口按当前工程解析；切换到道路编辑页不会卸载主端监听。同步版本单调递增，关闭后重新创建窗口不会停留在旧问题。原生命令校验窗口身份；生成过程中禁止编辑、映射和重试，定位仍可用。

定位保持窗口状态不变；用户可自行最小化、关闭或移出地图。原生窗口不提供页面内的键盘移动限制，使用 Windows 原生窗口移动/缩放能力。浏览器回退继续支持标题栏 Alt + 方向键移动及大小调整控件。

查明并修复的内存放大路径：

- 撤销历史原先每次深拷贝完整工程、最多 40 份。现在仅保存工程根快照，未变原始数据和成果通过不可变分支共享；撤销与重做仍保留实际编辑状态，不截断路线数据。
- 编辑路线原先逐个比较完整要素 JSON，长期 identity 缓存还保存所有几何的 JSON 文本。现在缓存短指纹，按稳定记录键或引用索引查找，仅对相同指纹的去重候选做精确内容比较。
- 当前路线切换不再重建未改变的来源数据、批量成果图层或整批显示副本。来源独立模板不随当前路线切换改变；各组件共享不可变的来源属性追溯对象。
- 编辑准备只把当前线部件交给 Worker 投影，取消旧准备任务；不对整份来源数据做重投影。已有源经纬坐标复用于参考线显示。
- 地图显示 Worker 每次处理最多 128 个要素、约 25,000 坐标的传输块，回复后才发送下一块。单个复杂要素保持完整，不当作来源总量限制；仅发送必要绘图属性，不复制整张源属性表。成果全局索引及追溯关系保持不变。
- 非顶点编辑模式不构造控制点 GeoJSON；编辑模式只显示视口内按网格去拥挤的控制点，保留完整路线索引及选中点。放大后可编辑更多点，不改变原始控制点或道路面。

工程原始几何、生产成果、显示几何和 MapLibre 瓦片索引仍会占用内存。本轮不是无限数据量、百万复杂面或全进程零内存溢出的承诺。更大规模仍需按 GeoPackage 空间索引和视口读取迁移，而不是把所有成果永久放在 JS 堆里。没有为了通过测试而对原始道路面单独 RDP 简化；未经拓扑验证的显示简化可能改变相邻车道接缝。

## 急弯圆角与车道表达

该轮规则版本为 `offset-local-loops-v3-outer-round-join`（后续 v5 局部修复见 [Hana 修复](hana-generation-fix.md)）。普通转角保留原 miter；仅凸外侧 miter 比例超过 2 时使用半径为偏移绝对值的圆角，每象限 8 段。凹内侧仍保留 miter 上限 8；真实掉头、退化、自交及组件交叠继续校验，不用任意中心线平滑掩盖问题。圆弧点保存源控制点和几何里程映射，相邻组件共享边界，自动设施按同一里程映射布设。圆角策略及数量写入需复核警告。此策略参考 [GEOS OffsetCurve](https://libgeos.org/doxygen/classgeos_1_1operation_1_1buffer_1_1OffsetCurve.html) 和 [JTS OffsetCurve](https://locationtech.github.io/jts/javadoc/org/locationtech/jts/operation/buffer/OffsetCurve.html) 的连接样式、miter 上限和圆角分段做法。

引擎响应及每个成果要素带左右车道数，车道面还带所属侧车道数量和实际 `lane_width_m`。当前路线摘要、工程属性显示左/右及总车道数量，依据逐记录映射或人工断面，不依据总宽度猜测。启用“道路标线”后，地图区分白色车道分隔虚线、白色边缘实线及中央黄色实线。标线样式是地图像素表达，不能作为施工标线规范验收或替代真实生产面的尺寸。

外侧圆角与完整路口连接建模不同，不承诺自动解决立交或匝道汇入重叠。

## 参考做法与下一阶段边界

- [PostGIS ST_OffsetCurve](https://postgis.net/docs/ST_OffsetCurve.html) 和 [ST_Buffer](https://postgis.net/docs/ST_Buffer.html) 提供圆角、斜接、斜角等连接策略；复杂折线偏移仍可能产生多段或空结果。几何有效不能替代业务车道语义。
- [SUMO 网络定义](https://sumo.dlr.de/docs/Networks/PlainXML.html) 把路口形状、车道和连接组织为独立对象。[SUMO FAQ](https://sumo.dlr.de/userdoc/FAQ.html) 也讨论急弯造成的路口形状问题和手工修正。
- [ASAM OpenDRIVE 连接道路](https://publications.pages.asam.net/standards/ASAM_OpenDRIVE/ASAM_OpenDRIVE_Specification/v1.8.1/specification/12_junctions/12_04_connecting_roads.html) 明确路口连接道路及车道连接；这不是把所有二维相交路线当作平交。

因此下一阶段应增加明确的路口连接、桥隧/层级和车道关联，再实现同层汇入边界裁剪、匝道渐变宽度与过渡连接面。层级未知的交叉保持独立，不自动融合。当前仍是逐路线生成，**尚未实现完整匝道接入、平交融合或立交遮挡模型**，不能宣称截图里的所有交叠已经解决。

## 真实数据验证

用户授权的表已通过只读连接导出到本机忽略目录 `artifacts/private-validation/20261004-gpsgd-original/`，保留 GeoPackage 和 WGS84 GeoJSON 副本；未改写数据库。原始数据、测试报告及凭据不提交到 Git。

副本共 3,672 个要素，拆分得到 3,660 个线部件，另有 13 个非线要素。统一测试模板为左右各三条 3.5 m 车道、中央隔离带 0.5 m，其他宽度为零，外侧偏移 ±10.75 m，场景关闭。该模板仅用于同输入新旧引擎对比，不代表数据库实际道路宽度。

| 指标 | 旧引擎 | 本轮引擎 |
| --- | ---: | ---: |
| 成功线部件 | 3,525 | 3,559 |
| 失败线部件 | 135 | 101 |
| 局部修整、需复核 | 0 | 34 |

上表是第一轮 v1 → v2 对比：新增成功 34 个，原先成功现在失败的回退为 0。单次引擎流式墙钟约 10.14 s / 9.62 s，非冷缓存受控基准，不包含桌面渲染，也不能推定速度提升幅度。报告位于同一私有目录的 `engine-comparison.json`。

本轮 v2 → v3 外侧圆角对比仍为 3,559 成功、101 失败、34 需复核，无新增恢复也无回退。真实样本没有触发外侧圆角警告，圆角改善由合成急弯测试验证，不能据此声称实际匝道都已修好。101 个失败中：参考线本身自交 76、超出局部修整范围的偏移环 15、组件自交或退化 6、miter/掉头 2、其他几何或属性问题 2。单次墙钟 12.95 s / 14.40 s，不作为性能结论。报告为 `engine-comparison-outer-round-v3.json`。

表中匝道编码非空的记录有 1,316 条，仅 286 条具有正数 `f018` 路面宽度，范围 5.5～28 m。字段名中未发现明确桥隧/层级字段；代码含义还需业务确认。路面总宽度不能唯一推导左右车道、隔离带和路肩。因此不自动把主路模板强套为真实匝道结构，也不擅自解释分类代码。
