# 路线数据选择与全量读取

## 本轮目标

旧界面把首批 500 条、来源批次翻页、表格翻页和另一个全量导入操作混在一起。用户要选择整条由大量碎段组成的路线时，容易只导入第一批。本轮把来源读取、表内选择、地图提交拆成明确的三步，但不要求用户手工翻来源批次。

1. 打开来源：支持分页的文件、GeoPackage/SQLite 和 PostGIS 自动继续读取全部记录，展示累计进度。内部按批请求仅是传输策略，不是来源总量截取。
2. 在表内搜索、筛选与勾选：表格分页只控制 DOM 展示数量，所有已读取记录可参与筛选和选择。确认全部读取完成后，可对来源全部匹配记录选择；读取未完成时明确显示当前已读范围。
3. 确认加载到地图：只有此操作修改工程；读取、停止、关闭不自动写地图。大量已选记录分块提交，保持原始字段与几何。

## 停止、恢复与查询

停止读取保留已经接收的选择表记录；在途调用返回后检查取消状态，迟到页不重复追加。继续读取从 `nextOffset` 开始；失败可重试该位置。更改来源条件开始新的来源查询，而不是只筛选首批记录。无效条件不得把上次有效结果冒充为新条件结果。

来源分页仍为独立查询，不是数据库固定快照。在源数据同时变化时，即使按主键排序，OFFSET 分页仍可能出现重复/遗漏；适配器能力及原生警告须保留，后续应采用稳定主键游标与一致性快照。

## 界面原则

采用现有蓝白桌面主题，来源与读取状态简洁呈现；文件标题仅显示文件名与图层，完整路径保留悬停提示。搜索常驻，复杂条件按需互斥展开；显示字段可按名称/注释查找，恢复常用列或显示全部。表头、选择列和序号列固定，选中行反馈明确；支持点行勾选、表头全选当前页、只看已选、50/100/200 条展示页及直接跳页。来源批次分页不再出现在界面，保留唯一的表格展示分页和底部主确认操作。搜索可叠加已应用表达式，来源条件改变后所有后续页使用新条件。

## 实际边界

没有设置来源总条数上限，但不代表无限内存。当前选择表和工程仍持有完整矢量对象；超大规模需逐步采用磁盘索引与按需属性表。单次 IPC、原生输出字节和超时仍有安全边界，资源失败必须明确报错，不能以残缺结果冒充完成。

未具备来源分页的适配器仍只能展示它返回的快照；能力不足时不伪造“全部读取完成”。这轮不新增 MySQL/MSSQL/Oracle/WFS 的完整分页能力，也不更改数据源本身。
